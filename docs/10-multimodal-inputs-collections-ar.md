# المدخلات متعددة الوسائط والتحصيل

## الهدف

تجعل ARQA كل واجهة قادرة على استقبال المعلومة من النص والصوت والصورة والمستند وواتساب، ثم تحويلها إلى **اقتراح تشغيلي قابل للمراجعة** مرتبط بالعميل أو المشروع أو المورد الصحيح.

## قنوات الإدخال والإخراج

| القناة | الإدراج في ARQA | الإخراج من ARQA |
| --- | --- | --- |
| النص داخل التطبيق | نموذج أو شريط أوامر موحد | نتائج وسجل نشاط |
| الصوت | تسجيل ← تفريغ ← فهم الأمر | رد مرئي وصوتي اختياري |
| الصورة | رفع/كاميرا ← OCR وتحليل | ربطها بعميل أو رحلة أو مستند |
| المستند | رفع PDF/صورة ← تصنيف واستخراج حقول | مسودة فاتورة/عقد/أمر |
| واتساب | Webhook للرسائل والمرفقات | رسائل معتمدة وتذكيرات وتحميلات |
| اختصار خارجي | زر سريع/ضغط مطول أو Shortcut ← تسجيل صوت | فتح شاشة مراجعة أو تنفيذ مؤكد |

## تدفق موحد

```text
رسالة / صوت / صورة / مستند
        ↓
حفظ الأصل مع هوية المصدر والوقت
        ↓
تفريغ أو OCR أو تصنيف
        ↓
فهم النية واستخراج الحقول
        ↓
حل الكيان: عميل، مشروع، مركبة، فاتورة…
        ↓
سياسة المخاطر والصلاحيات
        ↓
مسودة قابلة للتأكيد أو تنفيذ مسموح
        ↓
سجل تدقيق وربط بصفحة الكيان
```

لا يجوز للوسيط متعدد الوسائط أن يكتب حقولًا مالية نهائية مباشرة من نص أو صوت غير مؤكد.

## التحصيل والمطالبات

### البيانات

- ذمم المدينة: العميل، المشروع، المستند، المبلغ المستحق، الاستحقاق، العملة والحالة.
- خطة سداد: أقساط ومواعيد وقواعد تأخير.
- حالة مطالبة: جديدة، قيد المتابعة، وعد بالسداد، مسددة جزئيًا، متأخرة، مغلقة.
- تذكير: موعد، قناة، قالب، مسؤول، نتيجة الإرسال والرد.
- دفعة: وسيلة سداد، مرجع تحويل، مرفق إثبات، حالة مراجعة وربط بالذمة.

### القواعد

1. يولّد النظام مطالبات قبل الاستحقاق وعنده وبعده وفق سياسة العميل.
2. يقترح صياغة الرسالة ومرفقاتها، ويستخدم قالبًا معتمدًا للقنوات المقيدة مثل واتساب.
3. يسجل التسليم والقراءة والرد والفشل ولا يفترض نجاح الإرسال.
4. التحصيل الوارد من صوت أو واتساب ينشئ **مسودة استلام** حتى يطابقها مستخدم مخوّل بمرجع تحويل أو فاتورة أو ذمة.
5. عند عدم تطابق العميل أو القيمة، يفتح استثناءً ولا ينسب الدفعة تلقائيًا.

## الأوامر الصوتية

يتوفر شريط أوامر صوتية مشترك في كل شاشة، إضافة إلى زر اختصار على الهاتف أو سطح المكتب. يبدأ التسجيل فقط بعد ضغط المستخدم؛ لا يستمع التطبيق باستمرار.

### أمثلة

- «قسط عشرة آلاف جنيه على سيارة مصطفى فتحي»
  - النية: إنشاء قسط.
  - الحقول: 10,000 EGP، أصل/سيارة «مصطفى فتحي».
  - النتيجة: مسودة قسط على صفحة الأصل أو العميل بعد حل الاسم.

- «استلام دفعة تحويل فودافون كاش 30 ألف جنيه من شركة العالمية»
  - النية: تسجيل دفعة عميل.
  - الحقول: 30,000 EGP، Vodafone Cash، العميل «شركة العالمية».
  - النتيجة: مسودة تحصيل تنتظر المطابقة والتأكيد.

### سياسة التنفيذ

| نوع الأمر | السلوك الافتراضي |
| --- | --- |
| فتح صفحة أو بحث | ينفذ مباشرة |
| إضافة ملاحظة أو مهمة | ينفذ مباشرة مع إمكانية التراجع |
| إنشاء مسودة عرض/قسط/رحلة | ينشئ مباشرة كمسودة |
| تسجيل تحصيل أو تعديل رصيد أو إرسال مطالبة | يعرض تأكيدًا وصلاحية مناسبة |
| تحويل مال أو اعتماد محاسبي نهائي | لا ينفذ آليًا؛ يتطلب تحققًا واعتمادًا |

## تحليل الصور والصوت والمستندات

- **الصور:** OCR للنصوص، تصنيف الصورة، قراءة مستند دفع أو وزن أو إثبات تسليم، مع حفظ الأصل.
- **الصوت:** تفريغ صوتي يحتفظ بدرجة ثقة واللغة، ثم يمر على محلل النية والكيانات.
- **المستندات:** تصنيف عقد/فاتورة/إيصال/أمر توريد، ثم استخراج الحقول واقتراح الربط.
- **المراجعة البشرية:** أي حقل منخفض الثقة أو ذو أثر مالي يظهر في واجهة مراجعة، مع مقارنة الصورة أو الصوت بالأصل.

## خصوصية وسلامة

- موافقة المستخدم على التسجيل الصوتي، وإشعار واضح بمصدر المحتوى.
- لا تستخدم بصمة الصوت كمصادقة منفردة في الإصدار الأول.
- تحفظ المرفقات في تخزين ملفات محمي، مع وصول مؤقت وسجل تنزيل.
- تفصل مفاتيح واتساب والأجهزة عن بيانات العملاء والمعاملات.
