# الإشعارات الداخلية — 2026-10-03

## نطاق التنفيذ المثبت

تم تنفيذ مركز إشعارات **داخلي ودائم** للحسابات المصرّح بها. الإشعار سجل قاعدة بيانات مرتبط بمستخدم محدد؛ ليس رسالة بريد، ولا تنبيه متصفح، ولا إرسال إلى WhatsApp أو SMS.

| الجزء | التنفيذ |
|---|---|
| التخزين | جدول `user_notifications` مع المستلم، الفاعل، التصنيف، الأولوية، الرابط الداخلي، حالة القراءة، ووقت الإنشاء |
| منع التكرار | `dedupeKey` فريد؛ يتضمن معرّف المستخدم عندما يكون الحدث موجهاً إلى أكثر من مراجع |
| الخصوصية | كل قراءة أو تعليم كمقروء مقيد بـ `recipientUserId` في الخادم؛ لا يمكن للمستخدم تعليم سجل مستخدم آخر |
| الويب | عداد غير مقروء في الرأس، رابط في الشريط الجانبي، وصفحة `/notifications` ذات قائمة حقيقية وحالة فارغة واضحة |
| الجوال | عداد في رأس التطبيق، مدخل من الصفحة الرئيسية، وصندوق وارد محلي يعمل على Android/iOS/Expo Web مع بوابة مصادقة واضحة |
| التحديث | استعلام أثناء فتح مساحة العمل كل 30 ثانية، وسحب للتحديث في صندوق الجوال؛ لا توجد عملية خلفية مستمرة أو قراءة خفية |

## الأحداث التي تنشئ إشعاراً فعلياً

| الحدث | المستلم | الأولوية | مصدر التنفيذ |
|---|---|---|---|
| إرسال طلب شراء من مسودة | المديرون والمسؤولون النشطون، باستثناء مرسل الطلب | عالية | `purchaseRequests.submit` |
| اعتماد أو رفض طلب شراء | صاحب الطلب | عادية عند الاعتماد، عالية عند الرفض | `purchaseRequests.review` |
| إنشاء مسودة مراجعة مالية/مستند | المديرون والمسؤولون النشطون، باستثناء منشئ المسودة | عادية | `smartIntake.createDraft` و`POST /api/mobile/drafts` |
| إنشاء حمولة أو إذن استلام من الجوال | المديرون والمسؤولون النشطون، باستثناء منشئ السجل | عادية | `createGenericIntakeDraft` في مسارات العمليات المحمولة |

لا يوقف فشل التسليم الداخلي إدراج السجل التشغيلي الأصلي؛ يُسجّل خطأ الخادم فقط. هذا يمنع تحويل خدمة التنبيه إلى نقطة فشل لمسار مالي أو تشغيلي معتمد.

## واجهات الخدمة

### Web tRPC

| الإجراء | الحماية | النتيجة |
|---|---|---|
| `notifications.list` | جلسة مصادق عليها | قائمة الإشعارات الخاصة بالحساب مع حد أقصى 100 |
| `notifications.summary` | جلسة مصادق عليها | عداد غير المقروءة والعالية/العاجلة |
| `notifications.markRead` | جلسة مصادق عليها | تعليم إشعار الحساب فقط كمقروء أو `NOT_FOUND` |
| `notifications.markAllRead` | جلسة مصادق عليها | تعليم كل إشعارات الحساب غير المقروءة |

### REST للجوال

| المسار | الحماية | النتيجة |
|---|---|---|
| `GET /api/mobile/notifications/summary` | Bearer session | ملخص عداد الحساب |
| `GET /api/mobile/notifications` | Bearer session | القائمة، مع `unreadOnly=true` و`limit≤100` |
| `POST /api/mobile/notifications/:id/read` | Bearer session | تعليم إشعار الحساب فقط |
| `POST /api/mobile/notifications/read-all` | Bearer session | تعليم كل إشعارات الحساب |

## التحقق المنفذ

- تم توليد الهجرة `drizzle/0008_foamy_scream.sql` ومراجعتها ثم تطبيقها بنجاح.
- تحقق `SHOW CREATE TABLE user_notifications` من الأعمدة، المفاتيح، والفهارس بعد التطبيق.
- اختبارات مركزة: `18/18` لاختبارات خدمة الإشعارات، التحقق من مسارات الجوال، وعميل الجوال.
- بوابات المشروع النهائية: `135/135` اختباراً، `pnpm check`، بناء إنتاج الويب، و`apps/mobile pnpm exec tsc --noEmit`.
- تمت معاينة صندوق الإشعارات في Expo Web دون جلسة: يعرض بوابة مصادقة صريحة ولا يستدعي أو يعرض سجلات غير مصرح بها. لم تظهر أخطاء Console.

## حدود مقصودة

1. لا توجد إشعارات Push أو مهام خلفية؛ لذلك لا يزعم التطبيق تنبيهاً خارج فتح التطبيق.
2. لا تُنشأ إشعارات اصطناعية أو seed data لإظهار الواجهة؛ حالة الصندوق الفارغ حقيقية.
3. لا تنشئ الإشعارات أي اعتماد أو قيد أو إدراج جديد؛ فتحها ينقل المستخدم إلى مسار المراجعة فقط.
