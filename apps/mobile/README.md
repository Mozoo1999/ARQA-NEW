# NARQA EBOS Mobile

تطبيق جوال أصلي مبني على Expo وReact Native لمنصة **NARQA EBOS Operational Prototype v0.1-final**. الواجهة عربية باتجاه RTL، وتدعم الهاتف واللوحي عبر تخطيط سفلي للهاتف وقائمة جانبية للعرض العريض.

## الوظائف المتاحة في المصدر

تتضمن الشاشة الرئيسية مركز تشغيل، وشاشة **حاسبة سلسلة التكلفة** المرتبطة مباشرة بالحزمة المشتركة `packages/cost-engine`، وشاشة **تحليل الأوامر العربية** المرتبطة بالحزمة `packages/command-intake`. يعرض التطبيق النتيجة وسطور التكلفة والثقة والنية، ولا يسمح بحالة التنفيذ إلا بعد ضغط المستخدم على زر التأكيد. المدخل النصي متاح فعلياً؛ أما التقاط الصوت الأصلي ثنائي الاتجاه فيتطلب إضافة محرك Speech-to-Text أصلي واختباراً على جهاز فعلي.

## التشغيل المحلي

```bash
cd apps/mobile
pnpm install
pnpm start
```

لتشغيل نسخة المتصفح للتحقق السريع:

```bash
pnpm web
```

وللتشغيل على جهاز فعلي، افتح Expo Go وامسح QR الذي يعرضه Metro، أو استخدم `pnpm android` و`pnpm ios` عند توفر بيئة التطوير الأصلية المناسبة.

## البناء والتوزيع

تمت إضافة `eas.json` بملفات تعريف `development` و`preview` و`production`. لإنشاء APK داخلي بعد تسجيل الدخول إلى حساب Expo/EAS:

```bash
npx eas build --platform android --profile preview
```

ولإنشاء نسخة iOS:

```bash
npx eas build --platform ios --profile preview
# أو
npx eas build --platform ios --profile production
```

يتطلب البناء الإنتاجي توقيع Android وApple حقيقياً وحسابات المطور المناسبة. تم توليد مجلدي `android/` و`ios/` والتحقق من وجود ملفات المشروع، لكن لم يتم الادعاء بوجود APK أو IPA مُوقّع لأن إنشاء ملف توزيع فعلي يتطلب حسابات التوقيع وبناءً خارج بيئة التحقق الحالية.

## الهوية والصلاحيات

المعرّفان الأصليان هما `com.narqa.ebos` لنظام Android وiOS، والاتجاه `default` لدعم الهاتف واللوحي. يعلن الإعداد عن أذونات الميكروفون والكاميرا ومكتبة الصور برسائل عربية واضحة، مع دعم Expo Web للتحقق المتقاطع.

## التكامل مع النظام المؤسسي

المحركان المشتركَان قابلان للاختبار ضمن المستودع، بينما ربط جلسة المصادقة وعمليات OCR والاعتماد المالي وقنوات WhatsApp مع خادم NARQA EBOS يتطلب عقد API جوال موثقاً وإدارة جلسة أصلية. لا يحتوي هذا المصدر على بيانات وهمية أو APK غير حقيقي، ولا يعتبر هذه التدفقات مكتمِلة قبل اختبارها على جهاز فعلي ومع خادم مصادق عليه.

## تثبيت APK داخلي عند توفر الملف

بعد نجاح `assembleDebug` أو `assembleRelease`، يكون الملف عادةً داخل `android/app/build/outputs/apk/`. انقل ملف APK إلى الهاتف، فعّل السماح بالتثبيت من هذا المصدر عند طلب Android ذلك، ثم افتح الملف واضغط تثبيت. يجب حذف النسخ التجريبية القديمة إذا تعارضت مع المعرّف `com.narqa.ebos`. لا تُستخدم هذه الخطوات حالياً لتقديم ملف تنزيل؛ فمحاولة البناء الحالية لم تنتج APK بسبب توقف Gradle daemon أثناء تهيئة Expo/NDK، كما هو موثق في `MOBILE-VALIDATION.md`.

### تنزيل النسخة الداخلية المستقلة

تتوفر النسخة المصححة من خلال [تشغيل GitHub Actions الناجح](https://github.com/Mozoo1999/ARQA-NEW/actions/runs/32791994562). افتح الرابط، ثم اختر قسم **Artifacts** ونزّل `narqa-ebos-internal-release-apk`. فك ضغط الملف للحصول على `app-release.apk`، وانقله إلى هاتف Android (بمعمارية arm64)، ثم وافق على تنبيه **السماح بالتثبيت من هذا المصدر** الذي يظهر من مدير الملفات. تتضمن هذه النسخة `index.android.bundle` داخل التطبيق، لذلك لا تحتاج إلى Metro أو اتصال USB أو Wi-Fi بجهاز التطوير. احتفظ بملف APK مع قيمة SHA-256 المسجلة في `MOBILE-VALIDATION.md` للتحقق من سلامة النقل.

يتوفر أيضاً [رابط تنزيل مباشر لملف APK Release المستقل](/manus-storage/NARQA-EBOS-v0.1.0-standalone-release-arm64_bfc5fc47.apk). لا تستخدم ملف `app-debug.apk` السابق؛ فقد كان يعتمد على Metro. هذا ملف اختبار داخلي موقّع بمفتاح Debug ولا يُستخدم للنشر على المتاجر.
