# NARQA EBOS Mobile

تطبيق Expo/React Native أصلي لمنصة NARQA EBOS، عربي RTL، ويعمل على Android وiOS/iPad من المصدر نفسه. يركز على الإدخال التشغيلي المحكوم: الصوت أو النص أو الصورة أو PDF ينتج **مراجعة أو مسودة**؛ لا ينشئ التطبيق قيداً أو سجلاً تشغيلياً تلقائياً من تحليل محلي.

## الوظائف الموجودة

- شاشة رئيسية عربية متكيفة للهاتف واللوحي، مع اختصارات صوت، مستندات، فاتورة، تقارير، ومركز إشعارات.
- جلسة صوتية مرئية داخل التطبيق: إذن ميكروفون، نافذة استماع، أسئلة متابعة صوتية/نصية، ملخص، تأكيد أو رفض، ثم تنفيذ خادمي مصادق عليه فقط.
- تغذية صوتية عربية أصلية موحدة تتبع لهجة ملف التشغيل عند دعمها؛ النص المنطوق هو ملخص المستخدم فقط، ولا تُقرأ تعليمات داخلية أو prompts بصوت عالٍ.
- تحليل صور وPDF بصري خادمي منظم؛ PDF يعالج الصفحات بالتتابع، ويعرض الأدلة والثقة والتعارضات والصفحات غير المقروءة.
- اختيار جهة اتصال واحدة بإجراء واضح من المستخدم؛ لا قراءة SMS أو رفع دفتر عناوين.
- إشعارات داخل التطبيق للمراجعة والاعتمادات، مرتبطة بالمستخدم المصادق عليه.

## التشغيل المحلي

من جذر المستودع:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm --dir apps/mobile exec tsc --noEmit
pnpm --dir apps/mobile start
```

### Android محلياً

```bash
pnpm --dir apps/mobile android
```

يتطلب Android SDK وJDK متوافقين. لا تستخدم `Expo Go` لاختبار الوحدات الأصلية المضافة مثل التعرّف على الكلام أو المنتقي؛ استخدم development build أو APK مستقل.

### Expo Web

```bash
pnpm --dir apps/mobile web
```

Expo Web يفيد لمراجعة التخطيط وحالات عدم توفر المكونات الأصلية. لا يثبت توافر الميكروفون أو الكاميرا أو SecureStore أو جهات الاتصال في تطبيق أصلي.

أُنتجت حزمة Android داخلية مستقلة من تشغيل GitHub Actions [`37700480080`](https://github.com/Mozoo1999/ARQA-NEW/actions/runs/37700480080) من الالتزام `844f2978706653395e80e447eed228503cf94445`:

- package ID: `com.narqa.ebos`
- ABI: `arm64-v8a`
- JavaScript bundle: مضمّن داخل `assets/index.android.bundle`
- SHA-256: `8aa7dbbcd698f0dc34fd02f59c62b74660ed6c522c56aba48108d98cfcff4c2c`
- تحقق إضافي: ثبّت وشغّل CI نسخة `x86_64` منفصلة من المصدر نفسه على محاكي Android API 35؛ دليل المحاكي لا يستبدل اختبار الهاتف المادي.

### خطوات التثبيت

1. افتح [تشغيل GitHub Actions الناجح](https://github.com/Mozoo1999/ARQA-NEW/actions/runs/37700480080).
2. نزّل artifact باسم `narqa-ebos-internal-release-apk` وفك ضغطه للحصول على `narqa-ebos-arm64-v8a-internal.apk`.
3. انقل الملف إلى هاتف Android arm64.
4. قارن SHA-256 مع القيمة أعلاه.
5. افتح الملف من مدير الملفات، وافق على السماح بالتثبيت من ذلك المصدر، ثم اختر **تثبيت**.

> هذه حزمة اختبار داخلية موقعة بشهادة Android Debug، وليست ملف نشر متجر أو توقيعاً مملوكاً للمؤسسة. لا تثبت فوق تطبيق إنتاجي يملك المعرف نفسه ما لم تتطابق شهادة التوقيع.

## iOS وiPad

يحتوي `app.json` على المعرف `com.narqa.ebos` وإعدادات الهاتف/اللوحي. إصدار IPA قابل للتثبيت أو توزيع TestFlight يتطلب حساب Apple Developer، شهادات، provisioning profile، وفحصاً على جهاز مادي. لم يُنشأ IPA موقّع في بيئة المشروع.

## الاتصال بالخادم

تتطلب الميزات التي تكتب أو تقرأ بيانات تشغيلية:

- إكمال OAuth وإبقاء Bearer token في SecureStore الأصلي فقط.
- `apiBaseUrl` و`webOrigin` صالحين في إعداد Expo.
- خادم NARQA EBOS مع قاعدة البيانات وهجراتها المطبقة.

عند غياب الجلسة، يبقى التحليل أو الإدراج المحمي مقفلاً بدلاً من إنشاء بيانات محلية وهمية.
