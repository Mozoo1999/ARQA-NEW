# NARQA EBOS Mobile Validation

## نطاق التحقق

تم التحقق من مصدر Expo الموجود في `apps/mobile/App.tsx` على بيئة التطوير الحالية. يعرض التطبيق تخطيطاً سفلياً عندما يكون العرض أقل من 768px، وقائمة جانبية عندما يكون العرض 768px أو أكبر. لا يعتمد هذا التحقق على بيانات تجريبية خارج الحزم المشتركة أو على APK مُسبق البناء.

## رحلة الهاتف

1. يفتح المستخدم التطبيق فيظهر شريط NARQA EBOS والصفحة الرئيسية.
2. يختار المستخدم من الشريط السفلي **الرئيسية** أو **حساب التكلفة** أو **الأوامر الصوتية**.
3. في حساب التكلفة يغيّر المستخدم القيم، فتُعاد النتيجة من `packages/cost-engine/src/calculate.ts` ويظهر تفصيل السطور.
4. في الأوامر العربية يكتب المستخدم الأمر ثم يضغط **تحليل الأمر**، وبعد ظهور النية والثقة يضغط **تأكيد وتنفيذ الإجراء**. لا يوجد تنفيذ تلقائي قبل هذا التأكيد.
5. من بطاقة **وحدات EBOS الفعلية** يفتح المستخدم وحدة التنظيم أو المشتريات أو الحوكمة أو OCR أو التقارير في المسار المنشور للنظام.

## رحلة اللوحي

1. يفتح المستخدم التطبيق بعرض 768px أو أكثر فتظهر قائمة جانبية لمساحات التشغيل بدلاً من الشريط السفلي.
2. يختار المستخدم من القائمة الرئيسية أو محرك التكلفة أو الأوامر الصوتية، وتبقى مساحة المحتوى مرنة لتناسب الشاشة العريضة.
3. يمكن للمستخدم من بطاقة الوحدات الفعلية فتح التنظيم المؤسسي أو طلبات المشتريات أو حوكمة العمارة أو OCR أو التقارير بنفس مسارات النظام المنشورة.
4. تظهر شارة `TABLET VIEW` في الشريط العلوي لتأكيد نمط العرض الذي اختاره التطبيق.

## دليل المسارات المنشورة

| المشغل الأصلي | المسار | نتيجة HTTP من البيئة المنشورة | شرط الجلسة |
|---|---|---:|---|
| التنظيم المؤسسي | `/organization/company` | 200 | قد يطلب تسجيل الدخول لتنفيذ البيانات |
| طلبات المشتريات | `/procurement/requests` | 200 | جلسة مستخدم مطلوبة للإنشاء والموافقة |
| حوكمة العمارة | `/governance/reviews` | 200 | جلسة مستخدم مطلوبة للإضافة والتعديل |
| OCR والمستندات | `/ocr` | 200 | جلسة مستخدم مطلوبة للاعتماد |
| التقارير المالية | `/reports/export` | 200 | جلسة مستخدم مطلوبة للتقارير المعتمدة |

تم الحصول على نتائج HTTP باستخدام طلبات GET إلى `https://narqaebos-c2nmdy4n.manus.space` في 25 أغسطس 2026. تعني نتيجة 200 أن مسار الواجهة المنشورة موجود وقابل للوصول؛ ولا تعني تجاوز المصادقة أو إثبات عملية مالية دون جلسة مستخدم.

## OAuth والروابط العميقة

يحسب التطبيق رابط callback من `expo-linking` بالصيغة `narqa-ebos://oauth/callback`، ويستمع إلى الرابط عند تشغيل التطبيق أو أثناء عمله. زر **تسجيل الدخول** يستخدم `WebBrowser.openAuthSessionAsync` عندما يتم ضبط `EXPO_PUBLIC_AUTH_START_URL`، ويعرض بديلاً صريحاً لفتح نسخة الويب عندما لا يكون المتغير موجوداً. يلزم ربط نقطة بدء OAuth الأصلية الخاصة بالبيئة وتسجيل scheme لدى موفر المصادقة ثم اختبار العودة على جهاز Android وiOS؛ لذلك لم يتم اعتبار المصادقة الأصلية مكتملة أو مدعاة التحقق في هذه البيئة.

## نتائج الاختبار

- `pnpm exec tsc --noEmit`: ناجح.
- `npx expo export --platform web --output-dir dist-mobile`: ناجح.
- `npx expo prebuild --no-install --clean`: ناجح، وتم إنشاء مجلدي Android وiOS.
- إنشاء APK/IPA إنتاجي: غير منفذ في بيئة التحقق الحالية لعدم توفر حسابات توقيع Android/Apple وبناء فعلي على جهاز.

## محاولة APK الداخلي

تم فحص البيئة ووجد Java 21 وAndroid SDK محلياً بعد تثبيت command-line tools وplatform-tools وAndroid 35 وBuild Tools 35.0.0، كما قام Gradle بتثبيت NDK 27.1.12297006 تلقائياً. تم إنشاء مجلدي Android وiOS بنجاح عبر Expo prebuild. تعذر إكمال `assembleRelease` بعد محاولتين فعليتين لأن Gradle daemon اختفى أثناء تهيئة وحدات Expo/NDK، حتى بعد خفض الذاكرة إلى 768MB وتعطيل البناء المتوازي. لا يوجد APK ناتج صالح للتسليم، ولذلك لا ينبغي استخدام رابط تثبيت قبل تنفيذ البناء في بيئة Android ذات ذاكرة أعلى أو عبر EAS.
